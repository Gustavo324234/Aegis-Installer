**Estado:** DONE

## Contexto

Antes del lanzamiento público necesitamos un script de smoke test que valide que el sistema arranca y responde correctamente en un entorno limpio. El objetivo no es reemplazar los tests unitarios (ya existentes en CI) sino verificar el stack completo end-to-end: Installer → ANK → Shell → respuesta HTTP.

Este script va a ser la primera cosa que un contribuidor ejecute después de seguir el README de instalación. Tiene que ser simple, rápido (< 2 minutos) y producir output claro: PASS / FAIL por check.

---

## Trabajo requerido

### 1. Crear `Aegis-Installer/smoke_test.sh`

Script Bash con `set -euo pipefail`. Debe ejecutar los siguientes checks en orden y reportar `[PASS]` / `[FAIL]` por cada uno:

| Check | Comando / Criterio |
|---|---|
| Docker daemon activo | `docker info` retorna 0 |
| Contenedor ANK corriendo | `docker ps` muestra `aegis-ank` con status `Up` |
| Contenedor Shell corriendo | `docker ps` muestra `aegis-shell` con status `Up` |
| ANK health — puerto 50051 accesible | `nc -zv localhost 50051` retorna 0 |
| Shell BFF health — `/api/status` | `curl -sf http://localhost:8000/api/status` retorna JSON con `"state"` |
| Shell UI accesible | `curl -sf http://localhost:8000` retorna HTTP 200 |
| AEGIS_ROOT_KEY seteada | Variable de entorno no vacía en el `.env` |

Al final del script, imprimir un resumen:
```
=== Aegis Smoke Test Results ===
Passed: X/7
Failed: Y/7
```

Si algún check falla, el script termina con exit code 1.

### 2. Hacer el script ejecutable y con ShellCheck 0 warnings

El script debe pasar `shellcheck smoke_test.sh` sin warnings. Usar `|| true` solo donde sea semánticamente correcto.

### 3. Documentar en `Aegis-Installer/README.md`

Agregar una sección **"Smoke Test"** que explique:
- Cuándo correrlo (post-instalación)
- Cómo correrlo: `bash smoke_test.sh`
- Qué verifica cada check (una línea por check)

---

## Notas para el agente

- El script solo lee y valida, nunca escribe ni reinicia nada
- Si Docker no está corriendo, el primer check falla y el script termina — no continuar checks siguientes con `|| true` indiscriminado
- Usar `curl --max-time 5` para evitar cuelgues si el BFF no responde
- Leer el `.env` con `grep` para verificar AEGIS_ROOT_KEY — no hardcodear paths, usar la variable `$AEGIS_ROOT` si existe o fallback a `$(pwd)/.env`
- ShellCheck debe pasar: NO usar `[ ]` donde `[[ ]]` es correcto, NO usar `echo` para output de error (usar stderr)
- NO hacer push a git. Solo verificar que el script corre localmente en el servidor Debian
